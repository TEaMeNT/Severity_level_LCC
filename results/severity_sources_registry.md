## 1. Сводная логика каскада тяжести и принятия решения HARA

Для каждого прогона симуляции итоговая тяжесть рассчитывается как каскадный максимум трёх физико-кинематических компонентов по обоим участникам движения (`Ego` и `Target`, ISO 26262-3:2018 6.4.3.2 Note 1; `src/hara_lcc/simulation/campaign.py:189`, `src/hara_lcc/analysis/loader.py:121`):

$$S_{\text{run}} = \max\left(S_{\text{side}},\ S_{\text{barrier}},\ S_{\text{ditch}}\right) \in \{S0, S1, S2, S3\}$$

Итоговый класс тяжести каждой отдельной строки HARA (`1.1.A` и `1.1.B`; SAE J2980:2023 §5.2.1.5(g) и §5.2.2.2 Note 1) назначается строго по выборке состоявшихся ДТП ($N_{\text{crash}}$) по кумулятивному правилу **$> 10.0\%$** сверху вниз (ISO 26262-3:2018 Annex B Table B.1; SAE J2980:2023 Appendix B §B.2, с. 19; `src/hara_lcc/severity/iso26262.py:105-194`):
1. $P(S3 \mid \text{ДТП}) > 10.0\% \implies \mathbf{S3}$ (`>10% AIS 5–6`);
2. иначе $P(S3 + S2 \mid \text{ДТП}) > 10.0\% \implies \mathbf{S2}$ (`>10% AIS 3–6`);
3. иначе $P(S3 + S2 + S1 \mid \text{ДТП}) > 10.0\% \implies \mathbf{S1}$ (`>10% AIS 1–6`);
4. иначе $\mathbf{S0}$ (`AIS 0`, отсутствие травм).

**Контрольные пересчёты по классификатору `v1.1` (без изменения архивных CSV):**
* Архив `200 passive` (`results/lcc_hara_results.csv`, `N_crash = 199`): `1.1.A` ($n_A = 99$) $\to \mathbf{S1}$ ($P(\ge S2) = 2.0\%$, 95% ДИ $[0.25\%, 7.11\%]$), `1.1.B` ($n_B = 100$) $\to \mathbf{S2}$ ($P(\ge S2) = 17.0\%$, 95% ДИ $[10.23\%, 25.82\%]$; $P(S3) = 4.0\%$, 95% ДИ $[1.10\%, 9.93\%]$), главный итог `Worst-Case` $\to \mathbf{S2}$.
* Архив `400 passive` (`results/run_400/lcc_hara_400.csv`, `N_crash = 397`): `1.1.A` ($n_A = 199$) $\to \mathbf{S1}$ ($P(\ge S2) = 0.5\%$, 95% ДИ $[0.01\%, 2.77\%]$), `1.1.B` ($n_B = 198$) $\to \mathbf{S2}$ ($P(\ge S2) = 10.6\%$, 95% ДИ $[6.69\%, 15.75\%]$; $P(S3) = 3.0\%$, 95% ДИ $[1.12\%, 6.48\%]$), главный итог `Worst-Case` $\to \mathbf{S2}$.

**Маркировка статуса обоснования в таблицах:**
`[Стандарт / База ДТП]` — прямой норматив или статистика реальных ДТП (NASS-CDS / GIDAS / FARS / ITARDA); `[Краш-тест / Исследование]` — полигонные испытания или рецензируемая модель; `[Стендовая калибровка CARLA Config F]` — измерено на стенде `CARLA 0.9.16` (`test_shoulder_friction.py`); `[ТЗ / Сценарное допущение]` — задано проектной постановкой ODD; `[Инженерная эвристика]` — параметризация кода без единого нормативного числа.
